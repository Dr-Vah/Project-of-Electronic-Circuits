# 白球直线运送程序

这是独立于 `Task2` 巡线固件的找球/运球程序。摄像头在同一帧中识别白球和
涂黑的 1/4 圆停止区，三轮全向底盘先移动到球后方，再对准并直线推球。
程序不使用红外传感器。

> 上电后，只要白球和黑色停止区达到稳定确认，小车就可能开始运动。
> 首次调试请架空车轮或断开电机电源。

## 运球状态机

1. `WAIT_SCENE`：等待白球和黑色停止区同时稳定出现；
2. `STAGE_BEHIND_BALL`：横移到“黑区—白球”连线在球后方的延长线上；
3. `ALIGN_APPROACH`：停车并把白球、黑区共同对准画面中央；
4. `APPROACH_BALL`：低速直行接球；
5. `ALIGN_PUSH`：控球后再次停车对准；
6. `STRAIGHT_PUSH`：锁定 `vx=0`、`omega=0`，依靠轮速 PID 直推；
7. `FINAL_PUSH`：黑区进入近场后降速定时推进最多 0.5 秒，将摄像头下方不可见的球推入黑区；
8. `SETTLE/BACK_AWAY`：停车 300 ms，再直线后退释放球。

接球阶段若白球已经到达近场（中心纵坐标至少 `0.50` 且直径至少 `18 px`），
随后因底盘阴影消失而黑区仍可见，小车会沿已对准方向继续接近 500 ms，再进入
只依赖黑区的推球对准；远处丢球仍会停车并返回等待，不会盲目前进。

视觉帧超过 600 ms 没有更新时，控制器立即停止三个电机。接球后即使白球被
底盘遮挡，程序也会用最后一次球位继续锁定黑区。任意单帧确认球框与已锁定黑区
重叠时会立即停车，不再等待多帧；看不到球时，黑区底边到达画面高度 75% 后，
控制器最多低速盲推 0.5 秒，然后停车并后退释放球。黑区丢失不会被当作到达停止
区，而是按异常安全停车。

黑色停止区使用暗色连通域识别，默认灰度阈值为 `105`，至少连续 2 帧确认。
只有确认白球以后才会开始寻找停止区，避免在无球时把门后阴影当成目标。现场
左右各有一个黑块时，程序选择“位于白球更远处、与白球横向距离最近，并且前后
距离不超过画面高度 30%”的黑块。首次稳定确认后，检测器只跟踪该黑块附近的
连续目标，不再切换到其他暗区；白球附近的阴影也会因距离关系被排除。TFT 使用
绿色框显示白球、青色十字显示球心、
品红框显示本轮选中的黑色停止区。两条黄色竖线和红色轴线使用实际安装偏移：
原始网页画面中车体中心带为 `38%～48%`、直推轴为 `43%`；程序内部和 TFT
经过180度旋转，因此分别显示在 `52%～62%` 和 `57%`。

主要现场参数位于：

- `black_target_detector.c`：黑区灰度、面积阈值和检测区域；
- `main/ball_transport_controller.c`：对齐阈值、接球位置、速度和后退时间；
- `white_ball_detector.cpp`：白球亮度、色度、圆形和阴影阈值。

### 车体中心区域

控制器沿用四路伪红外的实际安装标定：总检测带宽为画面 `20%`，相对原始
摄像头中心向左偏 `7%`。中间两路对应原始画面 `38%～48%`。由于检测前进行
180度旋转，控制坐标中的中心带为 `52%～62%`，也就是归一化坐标
`center_x=+0.04～+0.24`。

站到球后方的粗调整阶段，白球只要位于这条中心带内就不再为小像素误差频繁
转向。正式接球和直推前则使用更严格的车头轴线：中间两块的中央分界线，也就是
`center_x=+0.14`。程序必须同时满足“白球与黑块横向重合”和“二者共同中心靠近
车头轴线”，从而区分“路线三点一线”和“车头确实朝向这条路线”。

## 白球检测器接口

调用方式：

```c
white_ball_config_t config;
white_ball_default_config(&config);

/* detector 约占 115 KB，建议放在静态区或 PSRAM，不要放在任务栈。 */
static white_ball_detector_t detector;
white_ball_detector_init(&detector, &config);

white_ball_result_t ball;
white_ball_detect_rgb565(&detector, rgb565_frame,
                         frame_width, frame_height, &ball);

/* 每收到并解码一帧摄像头图像后立即刷新屏幕。 */
white_ball_display_show_rgb565(rgb565_frame, frame_width, frame_height,
                               config.rgb565_byte_swapped, &ball, NULL);
```

识别步骤为：直接高亮或阴影内中灰候选提取、八邻域连通域、局部亮度差、
16方向圆周边缘、附近纸面检查和两次有效观测确认。中间允许短暂漏掉最多4帧，
确认后只接受上一位置附近且尺寸连续变化的候选，其他亮物体不能接管白球身份；
短时消失时仍保留原球锁定，直到设备重启。白球检测范围延伸到旋转后
画面的底边，避免近处球体被检测区域裁掉。阴影内的中灰候选还必须满足
较严格的圆度、填充率、直径和背景亮度条件。默认支持最大 `240 x 160` 图像，
并仅搜索完成180度方向校正后画面的指定区域，减少房间背景干扰。

该目录是独立的 ESP-IDF 5.4.x 工程。`main/main.c` 负责 USB UVC 摄像头
取流、JPEG 解码、白球/黑区识别、屏幕预览和 Wi-Fi 回传；
`main/ball_transport_controller.c` 是唯一发出底盘运动命令的模块。

现场优先调整：

- `minimum_luma`：默认210；球的高亮区域必须达到该亮度；
- `minimum_dim_luma`：默认100；阴影模式允许的最低球体亮度；
- `local_highlight_difference`：默认6；阴影中的球心需比对称外围纸面至少亮6；
- `maximum_chroma`：默认64；用于排除橙色灯等强彩色物体；
- `minimum_local_luma_contrast`：球必须比周围纸面至少亮10；
- `minimum_confidence`：总评分门槛，默认0.50；
- `minimum_area_px`：按白球在实际画面中的最小像素面积设置。

## 实时屏幕预览

初始化检测器时同时初始化屏幕：

```c
#include "white_ball_display.h"

ESP_ERROR_CHECK(white_ball_display_init());
```

屏幕使用项目现有的 128x160 ST7735S 接线：

| ST7735S | ESP32-S3 |
| --- | --- |
| VCC | 3V3 |
| GND | GND |
| CS | GND（必须接低，不能悬空） |
| SDA / MOSI | GPIO42 |
| SCL / SCLK | GPIO41 |
| DC | GPIO48 |
| RST | GPIO38 |

摄像头彩色画面保持宽高比并居中显示。识别到白球时，屏幕使用绿色矩形框住白球，
并用青色十字标出中心。没有识别到白球时仍正常显示未经标记的实时画面。
启动后屏幕会先显示蓝色自检画面；摄像头成功输出第一帧后才切换成实时画面。
如果一直停留在蓝色，表示屏幕正常，但USB摄像头尚未产生可解码的视频帧。

## Wi-Fi画面回传

固件启动后会建立热点 `ESP32-Camera-Debug`，密码为 `camera123`。电脑或手机
连接该热点后，在浏览器打开 `http://192.168.4.1/` 即可查看摄像头实时画面。
网页回传摄像头原始JPEG画面，并叠加绿色白球框、品红色停止区框、黄色车体
中心带边界和红色直推轴线；顶部状态栏同步显示白球与停止区检测状态。屏幕显示
经过180度校正且带识别框的画面，网页框坐标会自动转换回原始画面方向。

## 构建与烧录

在 ESP-IDF 5.4 命令行中执行：

```powershell
cd "D:\study\Project of Electronic Circuits\WhiteBallDetection"
idf.py set-target esp32s3
idf.py build
idf.py -p COM5 flash monitor
```

把 `COM5` 换成开发板实际串口。退出串口监视器使用 `Ctrl+]`。

首次构建时组件管理器需要联网下载 `usb_host_uvc` 和 `esp_jpeg`。烧录时可暂时
拔下USB摄像头，只保留ESP32-S3的下载串口；烧录完成后再给摄像头接入GPIO19/20、
5V和共地。
