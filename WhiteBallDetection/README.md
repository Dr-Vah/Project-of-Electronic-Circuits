# 白球、橙球依次运送程序

这是独立于 `Task2` 巡线固件的找球/运球程序。摄像头在同一帧中识别白球和
涂黑的 1/4 圆停止区，三轮全向底盘先移动到球后方，再对准并直线推球。
白球完成后小车后退释放球，随后原地左转搜索橙球；稳定识别橙球后停止转向，
复用相同的对准、接近和直推流程完成第二次运送。
程序不使用红外传感器。

> 上电后，只要白球和黑色停止区达到稳定确认，小车就可能开始运动。
> 首次调试请架空车轮或断开电机电源。

## 运球状态机

1. `WAIT_SCENE`：等待白球和黑色停止区同时稳定出现；
2. `STAGE_BEHIND_BALL`：只做横向平移，使红色前进轴底端、白球、黑区三点一线；横移速度上限为 `0.02 m/s`；
3. `ALIGN_APPROACH`：停止平移，只用短脉冲旋转，使上述连线与红色前进轴重合；
4. `APPROACH_BALL`：低速直行接球；
5. `STRAIGHT_PUSH`：三点一线确认后保持 `vx=0`、`omega=0`，依靠轮速 PID 连续直推，中途不重新对齐；
6. 终点停车：球框与黑区重叠，或黑区底边到达画面高度 `84%` 且仍清晰可见时立即停车，不再继续盲推；
7. `SETTLE/BACK_AWAY`：停车 300 ms，再直线后退释放球；
8. `TURN_TO_ORANGE`：第一球结束后左转搜索橙球，连续两帧识别后停车；
9. 再次执行步骤 1～7 推橙球，随后进入 `FINISHED`。

对齐采用严格的先平移、后旋转：程序先把球—黑区连线延伸到画面底边，令其与
红色轴线底端的误差小于 `0.055`；随后停止平移，以 `0.35 rad/s`
转动 55 ms（约 1.1°）后停车等待下一帧，直到整条线与前进轴重合。较高瞬时
轮速用于克服整车静摩擦，较短时间限制单次转角。放宽后的局部跟踪窗口
负责容纳相邻帧间的位置变化。橙球左转
搜索速度为 `0.30 rad/s`，最长 8 秒；第一帧识别到橙球就立即停车，并在静止时
完成第二帧确认。超时仍未识别到橙球会安全停车并进入 `FAULT`，避免无限旋转。
白球完成后的后退速度为 `0.03 m/s`、时间为 `8.35 s`，按轮速和时间估算约
后退 `25 cm`；橙球完成后仍只后退 `0.9 s` 释放球。

接球阶段若白球已经到达近场（中心纵坐标至少 `0.50` 且直径至少 `18 px`），
随后因底盘阴影消失而黑区仍可见，小车会沿已对准方向继续接近 500 ms，再进入
只依赖黑区的推球对准。三点一线一旦确认就成为提交点，之后小车持续直行，普通
漏检或画面偏差不会再触发中途停车或重新转向；漏检持续 1.5 秒后会无缝切入直推，
整段提交运行设有 12 秒安全上限，避免摄像头异常时无限前进。

视觉帧超过 2 秒没有更新时，控制器立即停止三个电机。接球后即使白球被
底盘遮挡，程序也会用最后一次球位继续锁定黑区。任意单帧确认球框与已锁定黑区
重叠时会立即停车，不再等待多帧；即使球被遮挡，控制器也会在黑区仍可见、其
底边到达画面高度 `84%` 时立即停车并后退释放球。
黑区消失不再被视为到达终点，也不会触发任何盲推；连续丢失会安全停车并报错。

黑色停止区使用八邻域暗色连通域识别，默认灰度阈值为 `105`。检测器单帧输出
候选，运动控制器仍要求白球与黑区组成的完整场景连续 2 帧稳定后才会起步。
只有确认白球以后才会开始寻找停止区，避免在无球时把门后阴影当成目标。现场
起点会同时识别两颗球并使用两个相互独立的黑区跟踪器：原始画面左侧黑区永久
标记为白球目标，右侧黑区永久标记为橙球目标。两侧都完成标记前小车不会起步；
完成白球、后退和转向后继续使用起点保存的橙球目标身份，不再按转向后的画面
左右重新分配。每个跟踪器从同侧候选中选择“位于球更远处、与球横向距离最近，
并且前后距离不超过画面高度30%”的黑块。首次稳定确认后，检测器只跟踪该黑块附近的
连续目标，不再切换到其他暗区；白球附近的阴影也会因距离关系被排除。TFT 使用
绿色框显示白球、青色十字显示球心、
品红框显示本轮选中的黑色停止区。两条黄色竖线和红色轴线使用实际安装偏移：
原始网页画面中车体中心带为 `38%～48%`、直推轴为 `43%`；程序内部和 TFT
经过180度旋转，因此分别显示在 `52%～62%` 和 `57%`。

主要现场参数位于：

- `black_target_detector.c`：黑区灰度、面积阈值和检测区域；
- `main/ball_transport_controller.c`：对齐阈值、接球位置、速度和后退时间；
- `white_ball_detector.cpp`：白球亮度、色度、圆形和阴影阈值。
- `orange_ball_detector.c`：橙球 RGB 色差、面积、长宽比和填充率阈值；
- `main/ball_transport_controller.c`：左转搜索速度和超时时间。

橙球检测针对实拍图采用 RGB565 色差分割，默认要求红色通道至少 `145`，且
分别比绿色、蓝色至少高 `38`、`55`。候选还必须为近圆形连通域并连续两帧出现，
从而排除画面中的大块木柜和左侧细橙线。现场光照变化时优先调整
`minimum_red` 和两个色差阈值。

### 车体中心区域

控制器沿用四路伪红外的实际安装标定：总检测带宽为画面 `20%`，相对原始
摄像头中心向左偏 `7%`。中间两路对应原始画面 `38%～48%`。由于检测前进行
180度旋转，控制坐标中的中心带为 `52%～62%`，也就是归一化坐标
`center_x=+0.04～+0.24`。

站到球后方的粗调整阶段，白球只要位于这条中心带内就不再为小像素误差频繁
转向。正式接球和直推前则使用更严格的车头轴线：中间两块的中央分界线，也就是
`center_x=+0.14`。三点一线判断使用球—黑区横向容差 `0.07`、二者共同中心到
车头轴线的容差 `0.055`，并要求连续两帧成立。接近对齐时，转向依据也从白球
是否位于宽中心带改为二者共同中心相对直推轴的误差。程序必须同时满足“白球与
黑块横向接近”和“二者共同中心靠近
车头轴线”，从而区分“路线三点一线”和“车头确实朝向这条路线”。

## 白球检测器接口

调用方式：

```c
white_ball_config_t config;
white_ball_default_config(&config);

/* detector 约占 115 KB，建议放在静态区或 PSRAM，不要放在任务栈。 */
static white_ball_detector_t detector;
white_ball_detector_init(&detector, &config);

white_ball_result_t ball;
white_ball_detect_rgb565(&detector, rgb565_frame,
                         frame_width, frame_height, &ball);

/* 每收到并解码一帧摄像头图像后立即刷新屏幕。 */
white_ball_display_show_rgb565(rgb565_frame, frame_width, frame_height,
                               config.rgb565_byte_swapped, &ball, NULL);
```

识别步骤为：直接高亮或阴影内中灰候选提取、八邻域连通域、局部亮度差、
圆周边缘、附近纸面检查和两次有效观测确认。初次确认采用“三帧内命中两帧”，
即两次位置相近的有效检测之间允许漏掉一帧；稳定锁定后也允许短暂漏帧。
确认后只在上一位置附近的小窗口内搜索，其他亮物体不能接管白球身份；稳定锁定
在本次白球运送流程中不会解除，即使暂时丢球也不会恢复全画面搜索。白球检测范围延伸到旋转后
画面的底边，避免近处球体被检测区域裁掉。阴影内的中灰候选还必须满足
较严格的圆度、填充率、直径和背景亮度条件。默认支持最大 `240 x 160` 图像，
并仅搜索完成180度方向校正后画面的指定区域，减少房间背景干扰。

该目录是独立的 ESP-IDF 5.4.x 工程。`main/main.c` 负责 USB UVC 摄像头
取流、JPEG 解码、白球/黑区识别、屏幕预览和 Wi-Fi 回传；
`main/ball_transport_controller.c` 是唯一发出底盘运动命令的模块。

现场优先调整：

- `minimum_luma`：默认210；球的高亮区域必须达到该亮度；
- `minimum_dim_luma`：默认100；阴影模式允许的最低球体亮度；
- `local_highlight_difference`：默认6；阴影中的球心需比对称外围纸面至少亮6；
- `maximum_chroma`：默认64；用于排除橙色灯等强彩色物体；
- `minimum_local_luma_contrast`：球必须比周围纸面至少亮10；
- `minimum_confidence`：圆周支持评分参考值，默认0.375（12/32）；
- `minimum_area_px`：按白球在实际画面中的最小像素面积设置。

初次锁定采用“三帧内命中两帧”改善远处白球的闪烁，圆周采样仍要求至少
`13/32`。初次确认的中心跳动仍严格限制为 `16 px`；稳定锁定后的局部搜索半窗口
扩大为 `64 px`，窗口内部不再额外限制相邻帧中心跳动，并可桥接连续 3 个漏检帧。
每次有效识别都会立即更新下一帧搜索中心，不再进行会落后于旋转动作的位置平滑。
锁定一旦建立就不会恢复全画面搜索，因此窗口外的远处白色圆形物体不能接管身份。
橙球相邻候选的中心跳动限制为 `40 px`。候选外围约 `1.35`
倍半径处还必须至少有 `20/32` 个采样点
符合白色泡沫地板特征（亮度至少 `145`、色度不超过 `30`）。该门槛允许橙球
入镜导致的自动曝光下降；白球搜索同时限制在原始画面上方 `72%` 的泡沫区域，
反光瓷砖及其光斑所在的下部区域不参与候选搜索。

## 实时屏幕预览

初始化检测器时同时初始化屏幕：

```c
#include "white_ball_display.h"

ESP_ERROR_CHECK(white_ball_display_init());
```

屏幕使用项目现有的 128x160 ST7735S 接线：

| ST7735S | ESP32-S3 |
| --- | --- |
| VCC | 3V3 |
| GND | GND |
| CS | GND（必须接低，不能悬空） |
| SDA / MOSI | GPIO42 |
| SCL / SCLK | GPIO41 |
| DC | GPIO48 |
| RST | GPIO38 |

摄像头彩色画面保持宽高比并居中显示。识别到白球时，屏幕使用绿色矩形框住白球，
并用青色十字标出中心。没有识别到白球时仍正常显示未经标记的实时画面。
启动后屏幕会先显示蓝色自检画面；摄像头成功输出第一帧后才切换成实时画面。
如果一直停留在蓝色，表示屏幕正常，但USB摄像头尚未产生可解码的视频帧。

## Wi-Fi画面回传

固件启动后会建立热点 `ESP32-Camera-Debug`，密码为 `camera123`。电脑或手机
连接该热点后，在浏览器打开 `http://192.168.4.1/` 即可查看摄像头实时画面。
网页回传摄像头原始JPEG画面，并叠加绿色白球框、品红色停止区框、黄色车体
中心带边界和红色直推轴线；顶部状态栏同步显示白球与停止区检测状态。屏幕显示
经过180度校正且带识别框的画面，网页框坐标会自动转换回原始画面方向。

## 构建与烧录

在 ESP-IDF 5.4 命令行中执行：

```powershell
cd "D:\study\Project of Electronic Circuits\WhiteBallDetection"
idf.py set-target esp32s3
idf.py build
idf.py -p COM5 flash monitor
```

把 `COM5` 换成开发板实际串口。退出串口监视器使用 `Ctrl+]`。

首次构建时组件管理器需要联网下载 `usb_host_uvc` 和 `esp_jpeg`。烧录时可暂时
拔下USB摄像头，只保留ESP32-S3的下载串口；烧录完成后再给摄像头接入GPIO19/20、
5V和共地。
