# 当前集成及调参说明

新工程保留原硬件接口、避障流程、白球后退距离及推送完成判定。两个源工程未改动。

识别以 BallDet v2 为基础。白球阶段要求白球有效；完成白球搬运并切换橙球阶段后解除此依赖。

黑块首次获取时在原有 3%–97% 横向 ROI 内寻找评分最高的两个候选，不要求左右半区各一个；同时看到两块时选择原图横坐标较大的一块，即右侧终点。锁定后按上一目标位置寻找邻近候选，可跨画面中线，并允许另一块离开视野。低帧率下不设固定位移门限，优先选择上一目标附近的候选。切换橙球阶段重新获取目标。纵向 ROI 和形状阈值保留。

摄像头标定轴仍为原图 43%、旋转后画面 57%，未改为画面中心。

循迹：滤波和微分只在新相机帧更新，避免同一帧被重复滤波和按 20 ms 计算微分突跳。KP 0.40→0.22，KD 0.08→0.015，转向上限 0.20→0.10 rad/s；直线速度 0.04→0.03 m/s，修正前进速度 0.035→0.025 m/s。

推球对齐：横移增益 0.045→0.025、上限 0.020→0.010 m/s，单次最多 80 ms。旋转由固定 0.35 rad/s 改为随误差变化的 0.06–0.18 rad/s，单次 40 ms。推送前旋转增益 0.30→0.18，上限 0.08 rad/s，单次 40 ms。20 ms 控制周期下停止最多额外延迟约一个周期；停止后等下一帧再修正。橙球搜索角速度 0.30→0.18 rad/s，搜索超时相应延长至 14 s。前进推球速度、后退速度和时间保持不变。

验证：ESP-IDF 5.4.4 / ESP32-S3 编译通过。直接调用实际黑块检测 C 函数的模拟图像回归测试通过：跨中线跟踪、另一块消失后保持目标、拒绝远处干扰、同半区首次获取、首次仍要求两块。参数需实机确认，不代表已消除所有振荡。

旧 README 中的识别行为以本文为准。

最新低帧率适配：首次只有一个黑块也可识别，不再要求同伴同时出现；跟踪取消 48 像素位移硬门限，在原 ROI 内优先匹配距上一目标最近的候选。两帧稳定确认仍保留。若原目标消失而只剩其他黑块，可能切换到该黑块；仅凭当前图像无法保证身份不变。此前关于首次两块和距离拒绝的说明及测试结果不再适用。

最新策略：丢线确认 150 ms 后直行 350 ms 再转角（0.03 m/s 下约多走 1 cm），重新看到线即恢复循迹。屏幕 CY 为实际裁剪 ROI、MG 为参考轴、R 为线中心，保留四通道黑色占比以观察丢线和终点判定。白球、橙球、黑块均一帧即可有效，同帧即可进入横移判断；丢失帧立即无效，不将缓存结果计入确认。横移阶段不再等两帧；接近球前和正式推送前仍停车确认两个连续有效对齐帧。此前两帧识别确认说明以本段为准。

针对相机曝光、运动模糊和低帧率补充：白球检测会根据当前帧背景亮度对灰度和色度做局部增益归一化；局部搜索失败时会在整帧重新搜索一次，避免球跨帧移动超过跟踪窗口后永久丢失。白球候选仍需要圆周梯度、低色度、上下亮度关系和边缘纹理约束；未直接放宽边缘阈值，以免把橙球或车体高光当成白球。对桌面图片样本的离线回归中，原图白球有效样本保持 12/12，亮度降低到 70% 时为 11/12，加入轻度模糊后为 10–12/12，橙球误报被过滤。实际相机画面仍需通过屏幕叠加确认。

转弯前直行等待调整为 600 ms（当前 0.03 m/s 约 1.8 cm），只在确认丢线后执行，期间重新检测到线会恢复循迹。

目标终点选择：首次同时看到两个黑块时，当前版本选择原图左侧黑块；原图坐标随后经过 180° 映射供控制器使用。后续帧按上一目标位置跟踪，可跨越画面中线。首次只有一个黑块时仍使用唯一候选。

球和终点出现后的第一阶段横移恢复为按帧脉冲：每当新相机帧同时提供有效球和终点且连线仍在车身轴线外，只发一个约 80 ms 的横移脉冲，脉冲结束停车等待下一帧；不会在低帧率期间重复使用上一帧命令。横移脉冲固定为 0.065 m/s，只根据误差符号决定方向。旋转对齐仍使用短脉冲。

横移停止条件改为线底部交点越过车身轴线并落到左侧约 2.5% 画面宽度时停止，用于提前量；不再等待线精确落在轴线上。近线和推送前旋转脉冲统一固定为 0.28 rad/s。横移固定为 0.065 m/s。

推球停止进一步提前：球框重叠判定允许白球中心从画面 40% 开始触发；黑块底边达到画面 60% 即停止，达到 45% 开始减速。

进入 ALIGN_APPROACH 后，短时视觉跳变不会立即退回横移。目标场景失效或线底部交点严重偏离需要连续 3 帧确认，期间停车保持当前对齐；三帧仍严重偏离才重新进入横移阶段。

横移停止增加了回退边界：若线已经偏到左侧超过 10% 画面宽度，不再直接进入旋转，而是先发反向横移脉冲拉回有效范围，避免 STAGE_BEHIND_BALL 与 ALIGN_APPROACH 循环时车辆没有任何运动。
